# tiles3d: 3D Tiles in Step Inside

OGC 3D Tiles (Google Photorealistic, swisstopo buildings and vegetation) around the eye while you step inside a photo, in both deck.gl engines (WebGL2 `deck/engine.ts` and WebGPU `deck-webgpu/engine.ts`). Off by default. Design and licence analysis: [reports/step-inside-google-3d-tiles.md](../../../reports/step-inside-google-3d-tiles.md).

## Flags

| Flag | Values |
|---|---|
| `?tiles3d=` (src/lib/flags) | `off` (default), `swisstopo` (buildings + vegetation), `buildings`, `google`, `all` |
| `?tiles3dBlend=` | `fill` (default): tiles only where the photo doesn't cover the view. `over`: tiles everywhere (alignment check) |
| `?tiles3dBias=<w>`, `?tiles3dDebug=on` | Datum, depth-bias and deck uniform debugging |

Google needs `VITE_GOOGLE_TILES_KEY` in `.env.local` (gitignored). Without it, Google is skipped with a console warning.

## Files

| File | Role |
|---|---|
| `config.ts` | Sources (URL, credit, datum, depth bias, display-only), flag parsing |
| `geoid.ts`, `geoid-data.ts` | EGM2008 N: 0.1° Alps grid (≤ 0.16 m), 1° global fallback. Generated by `scripts/tiles3d/make-geoid.py` |
| `frame.ts` | ECEF → the photo's ENU frame (a `@math.gl/core` Matrix4), minus N for ellipsoidal sources |
| `viewport.ts` | `EnuViewport`: the world camera as the structural geospatial viewport `Tileset3D` traverses with (ENU → lon/lat/h through the tileset's own placement, frustum planes from pose + fov, far plane = the 3 km near-field radius) |
| `tiles.ts` | `Tiles3DSet`: one `@loaders.gl/tiles` `Tileset3D` per source (`Tiles3DSource` + the bundled `Tiles3DLoader`, Draco from `public/tiles3d/draco`), the byte-cache unload policy, tile-content to `TileMesh` on load, credits |
| `content.ts` | `TileMesh` (plain typed arrays + an ENU matrix) from a loaded tile's post-processed glTF: node chain, i3dm instances, base colour / texture image, bounding sphere. No renderer objects |
| `material.ts` | The shading rules shared by both layers: GLSL (fill rule, dither, derivative shading), refraction lift, per-set fade / clear / eye values |
| `deck-tiles.ts` | `DeckTiles3D`, the framework-free engine adapter (`enter(lat, lon, eye)`, `update(view, width, height)`, `layer(...)`) |
| `deck-layer.ts` | `Tiles3DDeckLayer`: draws the set's visible TileMeshes as luma Models (i3dm instancing, log depth) |
| `../deck-webgpu/layers/tiles3d.ts` | The WebGPU port of `Tiles3DDeckLayer` (WGSL, reversed-Z depth), fed by the same `Tiles3DSet` |
| `tiles3d.check.ts` | Pure checks (CI `tiles3d`) |

`scripts/tiles3d/stream-probe.ts` streams a source through the whole pipeline in node (network, no GPU) and prints the TileMeshes.

## Streaming

Traversal is loaders.gl's (the one deck's `Tile3DLayer` uses), driven by our own `EnuViewport` instead of a Web Mercator viewport: our world is a plain ENU frame, so `DeckTiles3D.update({ position, viewMatrix, projectionMatrix, fovY, aspect }, width, height)` takes a pose (ENU world → camera, column-major, looking down -Z). An unchanged pose skips traversal once everything is loaded; a tile arrival re-traverses with the last viewport. Placement stays float64 on the CPU: ENU ← ECEF (geoid inside) × the loader's `cartesianModelMatrix` × the glTF node chain; i3dm instances (ECEF-scale translations) get the whole chain per instance, so the GPU only sees ENU-sized numbers.

- **Near-field mask.** The viewport's far plane sits at radius + |camera − eye|, so traversal culls tiles beyond 3 km and never requests them (no mask plugin).
- **Unload policy.** `Tileset3D` byte cache: 0.18 GB soft target, +0.07 GB headroom; unloads free the TileMesh GPU copies (`onDisposeMesh`) and close the image bitmap.
- **Google auth.** The key rides on the root URL (`root.json?key=…`); `Tiles3DSource` copies it and the session token onto every tile request. There is no token auto-refresh (the old plugin refreshed the session): a session older than Google's lifetime needs a reload.
- **Relative model URIs.** An i3dm names its model relatively (`../../Tree-1.glb`); `tileCoreApi` resolves those against the tile's own URL.
- **Decoding** runs on the main thread (the `bundled` loader entry has no worker); images decode to `ImageBitmap`.

## T2 and the licence gates

`?tiles3dObjects=on` (default off) feeds measured evidence, the nDSM (swissSURFACE3D − swissALTI3D, `concord/occl`) and swisstopo tile hit ranges, into the Step Inside depth split: `nearfield/object-prior.ts` promotes Far/Terrain cells to Object only when nDSM height ≥ 2.5 m and an independent range (anchored model, or tile hit) agrees with the DEM range. `buildNearFieldScene` takes it as the optional `objectPrior` input; the controller does not yet build the nDSM and tile-range grids, so that is the open hook. **Only measurable sources may feed it:** `isMeasurableSource` (config.ts) is false for any `displayOnly` source, and `applyObjectPrior` throws if one is listed, so Google can never reach the split. **Google logo gate:** `googleTilesPublicUseAllowed` is false in a non-dev build until the official logo ships; `tiles3dConfig` drops Google then (`TODO(pod-E attribution)` marks where the attribution component's readiness plugs in).

## Rules (don't break them)

- **Layer isolation.** The tile layers draw only in the world/step view (no three layer mask any more: `Tiles3DSet` holds data, not scene objects). In both deck engines, the layer isn't a terrain tile, so `PhotoCompositor` and the geometry pass skip it. `sampleAt`, horizon, silhouette, align, anchoring and concordance never see tiles. `scripts/tiles3d/step-tiles-check.mjs` asserts `sampleAt` is identical with tiles on and off.
- **Google is display-only.** It's hidden in the Truth view and in every export (`withoutDisplayOnly`), never read back and never cached beyond the browser's HTTP cache. Its credits come from `GoogleCloudAuthPlugin` (per-tile `asset.copyright`, sorted by occurrence) and show in `components/nearfield/Tiles3DCredit.tsx`. **Before any public URL, add the official Google Maps logo** (16–19 dp; not bundled yet).
- **Datum.** Google uses true ellipsoidal heights, so it's lowered by N. swisstopo's Cesium tilesets store MSL in the ellipsoid slot, as Rigi does, so N = 0. Both were measured at IMG_7018: Google's p25 (mesh − DEM) was −0.35 m, and swisstopo building bases sat a median −2.8 m.
- **Fill rule** (`TILE_GLSL_COMMON.tileCoveredByPhoto`): a tile fragment is dropped where the photo camera sees that surface (or sky), with a 0.4% edge feather. It's kept where the photo is occluded (a margin of 8% + 25 m) or masked (people and Object pixels). So the photo stays the truth inside its frame, and tiles fill beyond the frame and behind people.
- **Clear zones.** Tiles fade in from 25 to 40 m around the photo eye and from 5 to 10 m around the live camera. GPS is 7–37 m off, and a tile house at the eye would swallow the camera. The near field is the splats' job.
- **deck gotcha.** A layer that draws its own per-mesh Models must return them from `getModels()` and pass `draw(opts).shaderModuleProps` to Models it creates mid-draw. Otherwise the `project` uniforms stay unset and nothing renders.
