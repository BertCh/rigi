HOW TO RUN THE VERIFIERS (main session)
  1. Batches are listed in pack_index.json "suggestedBatches" (2 batches of 13–14 folders). All candidates of a photo
     are in one folder, so they always land in the same batch.
  2. Per batch: 2 fresh general-purpose verifier agents. Each gets its own scratch dir holding only a copy of that
     batch's pack/<folder>/ dirs. Never give them key/, pool.json, runs/ or this report.
     Instructions: the C1–C4 checklist of reports/bench-wild.md; near-miss = wrong; "unsure" only for unjudgeable
     skylines; one verdict per candidate_XX.jpg, returned as JSON {folder: {label: {verdict, tags}}}.
  3. Decision rule (as in tools/matcher/v2/verify/PROTOCOL.md): correct iff both say correct; wrong if either says
     wrong; otherwise unsure. If one verifier's duplicate pair (same cid, different width) disagrees, that verifier's
     verdict on that cid is unsure. Flag, but still report, a verifier who fails a positive control or accepts a
     decoy.
  4. Scoring: map labels via key/key.json candidates[label] (cid -> pool.json). Report construct-check agreement
     (expected: wrong) as the label-noise estimate for wrong-by-construction.
     Hard negative = verified wrong AND kept (common >= 100 or native fused >= 100). Add the 10 wrong-construct
     (subject to the noise check) and the 8 inherited-wrong.
