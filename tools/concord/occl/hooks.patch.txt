WP-F integration hooks (for the integration agent). NOT applied: WP-F edits no shared file.
All behaviour is behind the URL flag ?concord=occl. With the flag absent nothing below runs, no texture is
bound (the uniform uOcclOn stays 0), so output is bit-identical (parity when off).

Module API (src/lib/concord/occl):
  loadNearDsm(lat, lon, radiusM = 2000, resM = 2, opts?) -> Promise<NearDsm | null>   // ndsm.ts
      opts.wedge {yawDeg, halfDeg}: only km tiles in the view wedge; opts.maxBytes (default 4.5e6) caps
      the transfer nearest-first; opts.signal for abort. null outside CH. Throws on network failure (not
      cached; retry later). Frame = new EnuFrame(photo.lat, photo.lon, 0), the engine's own frame.
  occluderRange(g: GeomBuffer, cam: CameraX, dsm, objects?, people?, opts?) -> Float32Array   // occluder.ts
      photo grid, row 0 = TOP, metres, Infinity = nothing. cam.eye = engine world eye [0, 0, eyeAlt].
  occlTexture(occl) -> Float32Array (Infinity -> 1e7) for an R32F / R16F texture.
  OCCL_RULE {ratio 1.05, slackM 3}, occludedBy(r, o), OCCL_GLSL (GLSL1 texture2D helper occlDim).
Cost: occluderRange 320x240 = 170-225 ms CPU on dev photos (160x120 = 40-55 ms). Run it at 160x120 on the
main thread after each fresh geometry readback, or 320x240 in a worker; it depends on pose AND eye.

------------------------------------------------------------------------------------------ 5. gating / honesty
- Off when pose confidence is LOW (plan ground rule): skip loadNearDsm / leave uOcclOn = 0.
- The occluder is display-only: it never feeds pose, confidence, benchmarks or exports' measurements.
- Attribution when on: "Surface model © swisstopo (swissSURFACE3D, swissALTI3D)".
- Outside Switzerland loadNearDsm returns null without a request; occluderRange(dsm = null) then equals the
  DEM range (+ objects / people) and nothing dims beyond today's behaviour.
