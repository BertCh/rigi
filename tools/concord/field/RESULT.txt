API vs plan (additive / clarifying only)
  - fitField(cues, g, cam, opts) as planned. Cue residual: FieldCue = Cue & { residualPx: number | [dx, dy]; conf }.
    The plan typed residualPx as a number; a point needs two components, so points take [dx, dy] (px @1600,
    predicted − observed = the eval.ts sign; cue u,v = OBSERVED photo position). Edge: scalar along its normal;
    level / shore: scalar dy. A point with a scalar residual is rejected.
  - GeomBuffer was not defined anywhere; defined here: { w, h, rangeM (photo-uv grid, row 0 = top, ≤0/NaN = sky),
    people? }.
  - Extra opts: method "gp"|"tps", priorPx, fade, supportLengths, skyMarginPx, tpsLambda, maxObs, loo, confidence.
  - LOW refusal: displayField(confidence, …) returns null (nothing computed) unless the pose is accepted with
    confidence ≥ 0.5 (solve.ts acceptConfidence) or tier high/medium; missing confidence = LOW (fail closed).
    fitField(opts.confidence LOW) returns a zero field with provenance "refused:low-confidence" and never fits.
  - renderToPhotoUV(fInv, u, v, fwd?, iters?) — optional forward-field refinement (additive). The grid inverse alone
    has 0.12 px error next to the skyline; with refinement 0.0000 px.
  - "W = 0 on sky" clarification: sky cells within skyMarginPx (default 1.5·maxPx = 18 px) of terrain take that
    terrain's range, so W stays continuous across the skyline (a hard zero at the skyline would draw the rendered
    skyline twice or cut it). Sky beyond the margin is exactly 0 (unit-tested).
  - σ fade is applied along the principal axes of the 2×2 posterior covariance (a level/edge cue constrains one
    direction; fading by the unconstrained axis killed it). sigmaPx stored = σ of the best-constrained direction.
  - Defaults: ℓ = 200 px @1600, λ = 1 (ln range), bound min(12 px, 15 m at range, 1°), fade [0.6, 0.95]·s,
    support 2ℓ (tapered from 1.5ℓ), s = clamp(RMS residual, 1.5, 12). Defaults were NOT changed after the sweep
    (no configuration showed a real gain; see below).
