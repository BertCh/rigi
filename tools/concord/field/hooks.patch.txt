What it does
  - Both composites: declare the warp texture + scale + on uniforms, include WARP_GLSL (concord/field/glsl.ts),
    compute  vec2 uvG = warpUV(tex, scale, on, vUv)  once, and use uvG for ALL render-space reads: tLayer /
    layerTex (incl. layerAt under LOOK_REFINE), tGeo / geoTex (range, lr() silhouettes, isSkyline), inkLines()
    and revealAt() (both reconstruct render-space rays / ranges). tPhoto, tFg, tBrush, MASK() (refined masks
    are photo-space), swipe / lens / brush masks stay at vUv / uvT.
  - uWarpOn / warpOn = 0 (the default, and whenever setWarp(null)) ⇒ warpUV returns vUv itself ⇒ every
    texture read and the output are bit-identical to the current composite. Verified for the snippet on
    WebGL2 (tools/concord/field/glsl-check.mts: warpOn=0 ⇒ uvG ≡ vUv bitwise, three and deck dialects).
  - three: tWarp is a THREE.DataTexture (RGBA8, flipY=false, NEAREST, no mipmaps), row 0 = top;
    deck: warpTex via device.createTexture({data}) (row 0 = top, nearest), set through the compositor's
    setWarp → bump() → DeckEngine.updateComposite (composite-only change; terrain layers not rebuilt).
    Both sample it at (vUv.x, 1 − vUv.y) and flip dv, so the same field gives the same uvG in both engines
    (three-vs-deck dialect output bitwise equal in glsl-check).
  - Renderer.setWarp?(field | null) and renderUVOf?(u, v) (optional, additive). Callers MUST get the field
    from concord/field displayField(confidence, …), which returns null at LOW confidence (unit-tested).
  - Peak labels (three peakLabels; deck peakLabels) are moved to where their render point is SHOWN:
    WarpState.photoOf (grid inverse + 4 forward fixed-point steps). Visibility tests stay in render space
    (sampleAt at the unwarped projection); the people test uses the warped position. exportImage draws
    peakLabels, so exported IMAGES carry the warped labels (display), nothing else.

Deliberately NOT warped (plan §5: warps never feed pose, confidence, benchmarks or measurement exports)
  - engine.ts pinError (~L1950) and peaksInFrame (~L1885, candidates for pinning): pose inputs.
  - sampleAt(): it is a render-space query used internally (label occlusion, nearFieldDemRange). For a
    hover readout at a PHOTO pixel, call sampleAt(...renderer.renderUVOf(u, v)) at the UI call site.
  - skyline() (export label layout helper) stays render-space (≤ 12 px offset; cosmetic).
  - materials.ts uPhotoViewProj / deck world-view drape (plan: second PR; use WarpState.photoOf / the
    inverse texture), Step Inside splats, XMP/KML/pose exports.
Known caveat
  - Under LOOK_INK with comp_refine, inkLines(uvG) also reads MASK at uvG inside refinedSkyline(); the
    refined skyline is photo-snapped, so with the warp on it moves by W there. Owner of look/glsl may
    prefer to pass vUv for that term; harmless with the warp off.
  - deck peakLabels: placePeakLabels declutters in render space, then labels are moved (≤ 12 px).

Parity acceptance still to run by the integration agent (render lock): scripts/style-baseline.mjs 16/16
exact with the flag off, deck-vs-three composite < 1 LSB with the same field.
