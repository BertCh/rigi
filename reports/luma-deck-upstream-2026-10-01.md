## 1. Executive summary

- **No version bump is possible, and none would help.** Our luma pin `10.0.0-alpha.2` matches luma master in core, webgpu, webgl, engine and gpgpu. Master is only 3–4 commits past the tag. The one with runtime code is #3325, which adds new heightFog and precipitation shadertools modules, effects passes, and a deck yarn patch. There is no alpha.3 on npm. Every gpgpu and shadertools PR we care about (#3265–#3294, #3289, #3304, #3305, #3285, #3291) is already in our pin.
- **Our deck build matches PR #10752 exactly, but is 10 commits behind deck master.** Only one of those 10 runs on our code paths: d5c7695f (#10731, ViewManager try/finally plus a guard for a view with no view state). It is a robustness fix, not a live bug in our code.
- **The biggest new upstream material is luma's deck patch.** `.yarn/patches/@deck.gl-core-npm-9.4.0-707f3fb147.patch` (from #3325) fixes WebGPU Y-origin handling (viewport, pick scissor, picker readback), adds a `depth24plus` attachment to deck's render buffer 0, and fixes a WGSL `select` bug. These fixes are not in deck master, not in #10752, and not in any open deck PR. They are dormant for us today: the app uses the webgl-only build, has full-canvas views and no picking. They need fixing before the WebGPU renderer ships.
- **The real wins are local and need nothing from upstream:**
  - Use the GPUScan already in alpha.2 for the two hottest look kernels: `hz-scan` at about 0.49 ms per pass and `hz-offs` at about 0.45 ms per call. Both work on integers only, so the output stays bit-identical.
  - Expose the CPU node conditions alpha.2's graph already supports.
  - Build kernels with the engine `Kernel` class.
  - Collapse the duplicate sky-refine graph wrapper.
- **Two device workarounds can go once open PRs land:** #3312 `requiredLimits` and #3313 `WebGPUAdapter.attach`. Both are still open, unreviewed, and touch the same `_create()` as #3140/#3141. Do not vendor or patch them now.
- **Several workarounds have no upstream fix, open or merged.** We should contribute these ourselves:
  - raw `mapAsync` readback
  - raw `clearBuffer`
  - broken published manifests (`patch:` dependency, `~9.4` peer ranges)
  - LayersPass clear/depth control
  - `deck.finalize` not destroying the device
  - `Model.draw` without `firstInstance`
  - mipmap `submit` inside a pass
- **Upstream's new visual stack** (heightFog, sketch, pathDash, water, precipitation, scene buffers) mostly lives in a private, unpublished `@deck.gl-community/gpu-layers` package built on deck 9.4.0 plus a patch. Nothing in it should replace our atmosphere or haze fit. Two items are worth porting as MIT code, behind opt-in styles: the layered height-fog integral (Nebelmeer) and pathDash.
- **Watch:** the #10740–#10745 custom-projection stack merges silently onto #10752 and brings a stale `import {vec3} from '@math.gl/core'`. The re-vendor needs a grep gate for this. Merge conflicts will not flag it.
