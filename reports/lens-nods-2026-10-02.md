# Lens nods: luma.gl's Arisia program and Rigi (2026-10-02)

Status: landed in 113e218, toned down the same night. WIP, browser-unverified. Nothing was posted upstream.

**Decision (user, 2026-10-02):** be very subtle about name-dropping. Rigi nods to the program; it does not call it out. "Arisia" appears in no visible string; the only trace is the hover title of the `/dev/graph` glyph. "Lensman" appears nowhere in the app or examples.

Raw research (GitHub sweep, codename search, deck adoption, Rigi touchpoints, lore and naming limits): [`research_notes/arisia-lens-2026-10-02/`](../research_notes/arisia-lens-2026-10-02/), synthesis in its `SYNTHESIS.md`.

## Findings

- **What Arisia is.** "arisia.gl" is luma.gl's own name for its gpgpu stack: `GPUProgram` lowers to `GPUCommandGraph`, which runs on WebGPU (naming sections of luma PRs #3237 and #3250). Code identifiers were never renamed (`GPUProgram`, `GPUCommandGraph`, `GPUVector`, `Kernel`, `GPUIncrementalExecution`); the name lives only in doc filenames, branch names and PR bodies. The name comes from E. E. Smith's Lensman novels, where Arisia is home to the hidden mentors who make the Lens.
- **Timeline (visgl/luma.gl).**
  - 2026-09-11: the internal `jarnevon/*` stack (#3211–#3250); exploratory PRs #3240–#3249 closed on 09-12 as superseded.
  - 2026-09-14 merged: #3233 (graph state, value arena, transient lifetimes), #3237 (adaptive SpMV, PCG, Jacobi), #3250 (`GPUProgram` and command lowering).
  - 2026-09-15 to 09-17: about 21 `codex/arisia-*` PRs: #3258 command nodes, #3259–#3279 batching, #3281 Kernel migration (104 files), #3282 FFT2D, #3283 projection benchmarks, #3284 solver unification, #3292 fragmentation, #3294 `GPUIncrementalExecution`.
  - Roadmaps: `dev-docs/roadmaps/arisia-{kernel-migration,execution-lifecycle,solver-consolidation,fragmentation}.md`. Fragmentation evidence there: 16 chunks per operand, 4,096 → 512 dispatches, compile 174.4 → 2.3 ms (CPU / SwiftShader timings, not hardware GPU).
  - No Arisia-labelled work after 2026-09-17.
- **Ploor.** The only other Lensman word in any visgl repo. It names a future planner with an inspector over the compiler's lowering decisions (two mentions in luma's gpu-core lowering docs). Its branch `codex/arisia-ploor-inspector` is empty: head 5f988dcd (= #3283), 0 commits ahead of master, no PR.
- **No wider codename scheme.** No Eddore, Kinnison, Boskone, Mentor, Tellus or similar in luma.gl, deck.gl, math.gl, loaders.gl, vis.gl or the vendored tarballs. GitHub code search covers default branches only.
- **deck.gl has no compute graph.** Its only gpgpu use is the attribute buffer-group evaluator (#10518), which Rigi never enables. The compute-to-draw PRs in deck 9.4.0-rigi.2 (#10779 `BinaryAttribute.version`, #10778 frame timings, #10753, #10776) are vendored but not adopted. In Rigi, our own `ComputeGraph` (`src/lib/gpu/core/graph.ts`) runs luma's `GPUCommandGraph` on the render device, and deck-webgpu draws from its buffers. Copy must never say deck runs a compute graph.
- **What Rigi can show of the graph today.** `GraphInspection` (`src/lib/gpu/core/inspect.ts`) carries node kind, condition, workload bound and p50 CPU/GPU timings. luma's lowering decisions (why a realization was chosen) exist in `src/lib/gpu/core/program.ts` compile results but are not kept on the inspection record, so a Ploor-style "why" view needs a `gpu/core` change.
- **Naming limits** (not legal advice): no quotes, characters or art from the novels; no "Lensman" in the UI; a trademark containing "LENSMAN" exists in photographic goods. Generic words (lens, clear ether, perception) are fine.
