Status: WIP, browser-unverified. Nothing here was posted upstream.

Attribution: Names allude to E. E. Smith's Lensman series; no text or art is used; not affiliated. Arisia is luma.gl's program codename.

## Background

- Arisia is the upstream codename of luma.gl's gpgpu / `GPUCommandGraph` program (luma PRs #3237 and #3250 "Naming" sections). Code identifiers are not renamed (`GPUProgram`, `GPUCommandGraph`, `GPUVector`, `Kernel`, `GPUIncrementalExecution`). The name lives in doc filenames, branch names and PR bodies.
- Timeline highlights (visgl/luma.gl):
  - 2026-09-11: stacked exploratory PRs #3240-#3249 (closed 09-12 as superseded); #3233, #3237, #3250, #3251 opened.
  - 2026-09-14 merged: #3233 (graph state, value arena, transient lifetimes), #3237 (adaptive SpMV, PCG, Jacobi), #3250 (`GPUProgram` + command lowering).
  - 2026-09-15..17: `codex/arisia-*` series, 21 PRs: #3258 command nodes, #3259-#3279 batching, #3281 Kernel migration, #3282 FFT2D, #3283 projection benchmarks, #3284 solver unification, #3292 fragmentation, #3294 `GPUIncrementalExecution`.
  - No Arisia-labelled work after 2026-09-17.
- Branch `codex/arisia-ploor-inspector` exists upstream and is empty (head 5f988dcdd = #3283 tip, ahead 0, no PR). "Ploor" appears only there and in two luma lowering docs. The "inspector" is intent only. Rigi's `/dev/graph` provenance panel is Rigi's own, not a port.
- deck.gl has no `GPUCommandGraph` consumer. Its only gpgpu use is the attribute buffer-group evaluator (deck #10518), which Rigi never enables. The truthful Rigi statement is: a luma command graph (`src/lib/gpu/core/graph.ts`, `ComputeGraph`) shares the render device, and deck-webgpu binds its buffers. Copy must never claim deck runs a compute graph.
- Only two Lensman names exist anywhere in visgl (Arisia, Ploor). Every Rigi nod is Rigi-originated.
