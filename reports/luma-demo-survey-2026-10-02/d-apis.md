Not worth doing (checked):
- **luma shadertools `fp64`/`fp64arithmetic`/`dggs`:** Rigi keeps f64 on the CPU and sends camera-relative offsets (`geodesy.ts` header, `deck/batched-terrain-grid.ts`), so there is no f64 need on the GPU.
- **`experimental/gpu-project` `GPUProjection`:** terrain lat/lon → ENU is already GPU-batched.
- **`experimental/geospatial` `GPUHaversineDistance`/`GPUPointSpatialQuery`:** roll sizes are too small (`roll/spatial/neighbours.ts` is fine on the CPU).
- **`gpu-graph`, `gpu-trace`, `SpectralOceanSimulation`, effects TAA/GTAO/SSGI:** no Rigi use case.
- **`createGPUConjugateGradientProgram`:** no Poisson/CG solver in Rigi today. Keep in mind for depth hole-fill or gradient-domain blending.
- **`GPURasterTileHaloAssembler`/`GPURasterTileCache`:** a possible fit for cross-tile DEM ops (slope or hillshade at tile seams) only if seam artefacts appear. Speculative.

- npm: `latest 4.1.0`, `beta 5.0.0-alpha.11` (published 2026-10-02 19:15Z). Rigi pins core/proj4/types `5.0.0-alpha.10` and geospatial `5.0.0-alpha.9` (`package.json:54-56,94`). Installed: core, crs, polygon, proj4, sun, types and web-mercator at alpha.10; culling, dggs, geometry-utils, geospatial and wkb at alpha.9.
- alpha.10 (10-01): the bulk of the proj4 TypeScript engine (#142–#161: catalogue, datum and NTv2/GeoTIFF horizontal grids, typed-array batches, projection-specific batch kernels, native-PROJ qualification, lazy plugins, TypeScript `Projection` as default), **new `@math.gl/timezone`** (#158, #162), and explicit vertical-grid height transforms (#164).

Earlier v5 items already in Rigi's install: Quaternion/Matrix4 convenience methods (#54), Euler order fix (#97), Float16Array types (#72), glTF-shape culling (#100), `makeOBBFromRegion` hardening (#111), `geometry-utils`, `wkb`, `geoarrow`, `dggs` (S2).

- Rigi usage: 21 `@math.gl/core` imports (Vector3/Matrix4/Quaternion in pose, camera, tiles3d, nearfield, deck views), 1 geospatial (`tiles3d/viewport.ts` `Ellipsoid`), 1 proj4 (`concord/occl/swiss-cog.ts`, lazy).
- Hand-rolled helpers found (lessons 5, 6): `geodesy.ts` (toEcef, EnuFrame with refraction, Bowring inverse, spherical great-circle helpers; keep, it is the semantic hub), `tiles3d/frame.ts`, `export/camera.ts` (mat3 helpers, ENU rotation, iterative inverse, mat3ToQuat), `nearfield/lift.ts` (quatFromMatrix copy), `nearfield/roll/eyes.ts` (rodrigues), `pose6dof/ransac/rot3.ts` (keep), `body/anny.ts` (rotationFromAxisAngle, a model port; keep), `tiles3d/viewport.ts` `frustumPlanes` (fine, since loaders wraps it into math.gl `CullingVolume` itself).

### 2. luma.gl modules (vendored rigi.6 vs master a3ebdda13)

Export diff by package root (TypeScript AST, `dist/index.d.ts` vs `src/index.ts`; script `scratchpad/exports.cjs`):
- core: master **lacks** `BufferMapReadOptions`, `BufferReadOptions`, `getBufferReadTarget` (Rigi-local read-into-target/no-wait map commits). shadertools: master lacks `ShaderHookOptions` (#3286 head). splats: master lacks `SplatRADHierarchyData`, `SplatResidencyData` (#3340 head). experimental: master's root additionally re-exports the flow-particle, spectral-ocean and WebXR **types**; the classes are already in rigi.6 subpaths.
- engine, gpgpu, effects, webgpu, webgl: identical export sets.
- Conclusion: **no new luma runtime API since rigi.6.** rigi.6 is master plus PR heads plus local commits. Packages only in master and not vendored: `scene` (private, ANARI/glTF/USD import), `text` (private, SDF/bitmap atlases, `TextRenderer`), `gltf` (public, `createScenegraphsFromGLTF`, `exportGLTF`), `arrow` and `deck-arrow-layers` (private), `deck-gpu-layers` (private; `WaterSurfaceLayer`, GPUVector-first core layers #3169). None is needed now; `gltf` would only matter if tiles3d content rendering were redone on luma scenegraphs (`tiles3d/content.ts` draws meshes directly, which suits it).
- Rigi already adopts much of gpgpu: GPUSort, Reduction, Convolution, Compaction, Gather, Histogram, GroupAggregation, KMeans, FFT1D/2D, Scan, FiniteDifference2D, Transpose, Elementwise, SegmentedSort, SimilaritySearch, GridIndex, ReadbackRing, the inspector/preflight, gpu-raster dilation/gradient, splats. Unused but present: see lesson 9 and "not worth doing".
- Open luma PRs (25): every one Rigi vendors is unchanged except **#3346, whose head moved** (`680dc602` → `50622256`, a test-only commit). #3354 and #3344 are on `9.3-release` and do not apply. Watch: i#3329 (typed shader-module exclusions), deck #10627 (worker SplatLayer), and deck **#10752, whose head moved** (`d6c4ba79`, a master merge plus review feedback; it still pins loaders `^5.0.0-alpha.7` and math `^5.0.0-alpha.9`).

### 3. loaders.gl (origin/master 300f837c7; Rigi on 5.0.0-alpha.7, npm beta = alpha.7, published 09-25)

Since alpha.7, in the modules Rigi touches:
- **tiles:** #4056 FOV-aware SSE (lesson 2); #4053 `traverseTilesetContents` (camera-independent traversal, useful for offline bakes or prefetch of a whole tileset subtree; Rigi has none today); #4067 + #4073 RequestScheduler debounce fix; open #4089/#4090/#4092 (skip-LOD, faster refinement, parser import waits).
- **geotiff:** #4088 preserves numeric bands and geodetic metadata. It does **not** address the audit §8 reasons (no per-tile byte budget, ~8% over-fetch), so keep the rejection.
- **las:** #4093/#4095/#4096/#4098 (LASzip v1, pointwise LAZ, recovery, extra bytes). swissSURFACE3D ships as LAZ, but Rigi uses the 2 m raster DSM, so this is not needed now. Possibly relevant to Step Inside near-field geometry later.
- **v5 cleanups:** #4031 removes deprecated cache/option aliases, #4042 flattens source parser options, #4046 reduces the dependency footprint. Check `tiles3d/tiles.ts` options on the bump.
- No changes to terrain or quantized-mesh (Rigi decodes Mapterhorn Terrarium PNG on the GPU; not applicable). Arrow/GeoArrow/PMTiles work (#4019, #4080, math.gl geoarrow) has no current Rigi consumer.

### Re-check of the audit §8 rejections

- `@math.gl/sun`: no code change since alpha.6, so the 0.27°/0.86° error stands. Rejected.
- `@math.gl/geoid`: no change. proj4's new vertical grids (#164/#165) could wrap Rigi's own regional grid (`tiles3d/geoid.ts` + `geoid-data.ts`, 0.1° Alps ≤ 0.16 m) but add no data and no accuracy, so keep `geoid.ts`. If LHN95/CHGeo2004 precision is ever wanted, `loadVerticalGeoTIFFGrid` is the hook.
- `@loaders.gl/geotiff`: see above. Rejected.
