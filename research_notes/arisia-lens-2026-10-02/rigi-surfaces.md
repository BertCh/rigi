## 1. Design rules any nod must obey

From memory notes and repo docs:

- **Minimal strokes** (feedback-minimal-section-strokes, 2026-10-01): no outlines around sections/cards; separate by fill and spacing. Strokes only for state (focus, selected, input, toned warning). **No colored glow or drop shadow as decoration.** So: no glowing lens rings, no lens-flare, no bordered badges. A thin lens circle is acceptable only as data (a mark that carries meaning) or as an `ember` selected state.
- **Brand palette = Brezine/khipu** (brand-palette-khipu): no new literal hexes. Use `var(--rigi-*)` in CSS, `BRAND.*` / `brandVar()` in SVG. Roles: ink LK, paper W, glow YB `#bb8b54`, ember SB (selection/active only per Wave 5), lesson SY, trap PK, result PG, negative MG. Lensman's Lens glows in many colors; Rigi must pick one chart swatch (`glow` YB, or a Brezine code via `BREZINE`), never a rainbow.
- **Gipfelbuch softer** (feedback-gipfelbuch-softer): no grain, texture, tape, tilt, margin rule, frame ticks. **Gipfelbuch hand pass** (gipfelbuch-hand-pass): hand-written, all visuals sketches, >=6 hand notes per page, raw SVG `<text>` banned (use `HandLabel`/`HandNote`), data marks within 0.5 px, photos and DEMs never filtered. A Lensman marginal note there must be a hand note, countable toward the 6, and must not become a texture.
- **Landing scroll traps** (feedback-landing-no-scroll-traps): no wheel zoom in embeds, touch pan-y only. **Landing perf** (landing-perf): below-the-fold sections mount via `NearViewport`; do not add JS to the hero or start GPU work. The hero must ship little JS.
- **How-it-works scene** (how-it-works-scene): the user said "don't mess with existing stuff too much". It is frozen at the end under webdriver/reduced motion, labels are screen-pixel 2D boxes. Nothing may break the "Guess, measure, correct, snap." tagline.
- **Theme**: light and dark; use `brandVar()` on the page ground; always-dark islands marked `data-theme="dark"`. Add `light:` variants for off-palette colours.
- **Honesty** (AGENTS.md, WAG notes): do not claim a feature the code lacks; "say plainly when not measured". A nod must not assert upstream status ("arisia.gl") as fact. **No upstream posts without the user's OK** (whole-app-graph).
- **Subtle means rare**: one idea, repeated in at most a few places, never in the main call to action or hero headline.
- **Process rules** (cook-mode-coordinator, testing-never-blocks-dev): no browser runs, no render lock; land marked "(WIP, browser-unverified)"; one row per unit in `reports/batch-ledger.md`; commit only your own paths (`git commit -- <paths>`), never `git add -A`. New files need the `// Rigi` + SPDX header (`node scripts/ci/spdx.mjs`); run `npx biome check --write <files>`. Examples follow luma style (2-space, single quotes, 100 cols) and import only public `@luma.gl/*`/`@deck.gl/*`, never `src/`.
- **Naming**: full descriptive names, verbNoun functions (AGENTS.md). Do not rename existing abbreviations.
- **Licensing**: Lensman / "Doc" Smith names and the novel text are not ours. Use at most the one-word codename `Arisia` and the generic noun "lens"; no quotes from the books, no character names in UI; mention nothing under `NOTICE.md` unless text is quoted. (Judgment call, flag for the user.)
