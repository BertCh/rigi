## A. Background brief

### A1. What Arisia is (and is not)
- "arisia.gl" is the declared public name of the luma.gl gpgpu / GPU command graph program (PR #3237 and #3250 "Naming" sections). Code identifiers are not renamed: `GPUProgram`, `GPUCommandGraph`, `GPUVector`, `Kernel`, `GPUIncrementalExecution`. "Arisia" lives only in doc filenames, branch names and PR bodies. Earlier internal lineage name: `jarnevon/*` (40-PR stack #3211..#3250, 2026-09-11; #3240-#3249 closed 09-12 as superseded).
- Source of the name: Arisia = planet of the Arisians (E.E. "Doc" Smith's Lensman novels), the unseen mentors who forge the Lens. Here: the guiding program/compiler layer above the command graph.
- Only two Lensman names exist anywhere in visgl: **Arisia** and **Ploor**. Zero hits for Lensman, Eddore, Boskone, Kinnison, Mentor, Tellus, etc. in luma, deck, math, loaders, vis.gl, or the vendored tarballs. Every Rigi nod is therefore Rigi-originated.
- **Ploor** appears only in branch `codex/arisia-ploor-inspector` and twice in luma docs (`docs/api-reference/experimental/gpu-core/gpu-program-lowering.md`, `gpu-operation-lowering.md`): "planner/compiler interface that Ploor can later own", "Ploor planning/execution boundaries". The branch (head `5f988dcdd`, 2026-09-16, = #3283 tip) is EMPTY: ahead 0, behind 34, no PR. The "inspector" is intent only; no UI spec. Likely seed: #3232 `jarnevon/gpu-value-inspector`. Rigi is free to own the idea.

### A3. How deck uses it (corrects the premise)
- deck.gl has NO `GPUCommandGraph` consumer. Only gpgpu use: `modules/core/src/lib/attribute/attribute-buffer-groups.ts` (evaluator tree: `GPUDataEvaluator`, `interleave`, `cleanEvaluateSync`), merged as deck #10518 (2d096cce, 2026-08-04), WebGPU only, only when an attribute sets `settings.bufferGroup`. Rigi never sets `bufferGroup`.
- Compute-to-draw handoff PRs (all vendored in deck 9.4.0-rigi.2, none adopted by Rigi): #10779 `BinaryAttribute.version` + `dataRange` (the "compute rewrote a buffer in place" signal), #10778 `_onFrameTimings` per-pass GPU timing (Rigi has its own `src/lib/deck-webgpu/frame-timings.ts`), #10753 WebGPU padding for 8/16-bit x3, #10776 fp64 external buffer, #10752 luma 10 bump. Also #10576 `x/fp64-gpu` (open), #9919 `memory: 'gpu-only'` (open).
- Naming trap: luma `modules/gpgpu/src/gpu-graph/` is graph theory (BFS, PageRank), unrelated.
- Rigi truth: "luma command graph feeding deck". Rigi's `ComputeGraph` (`src/lib/gpu/core/graph.ts`) over `GPUCommandGraph` shares the render device; deck-webgpu binds the graph's storage buffers. Copy must never claim deck runs a compute graph.
- Graph concepts a photo can show: compute/render/copy nodes; edges = declared buffer use; topological waves; transient aliasing; CPU/GPU-indirect conditions (skipped node = closed shutter); preflight (`fitsDeviceLimits`); inspector p50/p95; `compilation.lowering.decisions` (why a realization was chosen); readback ring (keyhole); islands/realms (manifest I0-I12).
