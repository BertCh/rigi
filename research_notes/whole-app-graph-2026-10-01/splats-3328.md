## A. Compute + render in one GPUCommandGraph
- Graph built per rebuild: `new GPUCommandGraph(this.device, {id:'gaussian-splat-render-graph'})` S/gpu-splat-graph-renderer.ts:~516; `graph.compile()` :686 (compile once, freezes graph); per frame `this.compiledGraph.encode(commandEncoder, {parameters: undefined, buffers: this.getSourceBufferOverrides()})` :432. Caller owns the CommandEncoder + submit.
- Resources are all *imported* caller-owned buffers: `graph.importBuffer({id,byteLength,usage}, buffer)` (:574, :980), `graph.createDataView(handle,{format:'uint32',length})` (:1045). Per-frame replacement of imported buffers via `encode(..., {buffers:{id: ...}})`. No graph-created transients for the splat path; no importTexture/frameTextures used.
- Node APIs used: `graph.addComputePass({id,resources,compile})` (:714, :759, :835), `graph.add(new GPUSort({...}))` (:612; GPU radix sort primitive expands to command nodes via add() -> getCommandNodes), `graph.addRenderPass({...})` (:655). addCopyPass is not used in splats (G/gpu-command-graph.ts:931 exists: encodes directly on encoder).
- Compute node shape: `{id, resources:[{buffer,usage:'storage-read'|'storage-write'|'storage-read-write'|'uniform'}], compile:({device})=>({encode:({computePass,getBuffer})=>{...}})}`. Usage strings (G/gpu-command-graph-types.ts:35-43): storage-read, storage-write, storage-read-write, uniform, copy-source, copy-destination, indirect, vertex, index. Hazard inference: indirect/vertex/index count as READS (gpu-command-graph-compiler.ts:556) so compute-write -> render-indirect-read gets a RAW dependency automatically. Consecutive compute nodes coalesce into one compute pass; a render node ends the active compute pass (gpu-command-graph.ts:~1668).
- Indirect draw args produced on GPU: `DrawCommandBuffer` (G/draw-command-buffer.ts:75) wraps Buffer with usage STORAGE|INDIRECT|COPY_DST|COPY_SRC (:104). Splat ctor: `new DrawCommandBuffer(device,{id,type:'draw',commands:[{vertexCount:4,instanceCount:0}]})` S/gpu-splat-graph-renderer.ts:197. `importToGraph(graph)` (:~140) returns {buffer, words, instanceCounts (stride view of word 1), firstInstances}. Init compute pass declares `{buffer: drawCommands, usage:'storage-write'}` (:718); projection pass `storage-read-write` and atomically increments instanceCount (:769, :792 binds getBuffer(drawCommands)).
- Render node (S/gpu-splat-graph-renderer.ts:655-684):
  ```
  graph.addRenderPass({ id:'gaussian-splat-indirect-render',
    resources:[{buffer:projectedRecords,usage:'storage-read'},{buffer:sortedIndices,usage:'storage-read'},
               {buffer:firstUniform,usage:'uniform'},{buffer:drawCommandViews.buffer,usage:'indirect'}],
    compile:()=>({ getRenderPassProps:()=>({id,clearColor:this.clearColor,clearDepth:1,clearStencil:false}),
      encode:({renderPass,getBuffer})=>{ renderPass.setPipeline(this.model.pipeline);
        renderPass.setVertexArray(this.model.vertexArray);
        renderPass.setBindings({graphUniforms:getBuffer(firstUniform),projectedRecords:getBuffer(projectedRecords),sortedIds:getBuffer(sortedIndices)});
        this.drawCommands.draw(renderPass,0); } }) })
  ```
  `DrawCommandBuffer.draw` (G/draw-command-buffer.ts ~:170) = `renderPass.drawIndirect(this.buffer, byteOffset)` or `drawIndexedIndirect` for 'draw-indexed'. So the splat path does NOT use Model.draw; it manually setPipeline/setVertexArray/setBindings on the graph's RenderPass with a Model's pipeline+vertexArray, then raw drawIndirect. (RenderPass.drawIndirect(buffer, byteOffset?) already exists in core: render-pass.d.ts:113/115, and in vendored 10.0.0-alpha.2-rigi.1.)
- Attachments: splat render nodes use NEITHER graph `attachments` NOR a framebuffer: getRenderPassProps returns only id/clear*, so `commandEncoder.beginRenderPass(props)` (G/gpu-command-graph.ts:1690) targets the default canvas framebuffer (the swapchain / device default canvas context). Frame-scoped canvas textures could come via `encode(...,{frameTextures:{id:binding}})` (types :816) - not used by splats.
- Conditions: compute nodes may have CPU 'skip' or GPU 'indirect' (x==0 indirect dispatch) conditions (types :524-539); render/copy nodes take ONLY GPUCommandGraphCPUCondition (types ~:555-640). So GPU culling of a render node = indirect draw with instanceCount 0, not a condition.

## Composition recipe with a graph count buffer
1. Create buffer `device.createBuffer({usage: Buffer.STORAGE|Buffer.INDIRECT|Buffer.COPY_DST|Buffer.COPY_SRC, byteLength:16 (or 20)})`, or `new DrawCommandBuffer(device,{type:'draw'|'draw-indexed',commands:[{vertexCount:N,instanceCount:0}]})` (writes constant words once). Import: `const h = graph.importBuffer({id,byteLength,usage:buf.usage}, buf)` or `drawCommands.importToGraph(graph).buffer` (+ `.instanceCounts` view).
2. Compute node(s): `resources:[{buffer:h,usage:'storage-read-write'}]` (or 'storage-write' if rewriting all four words each frame; the splat renderer does an init pass writing 0 then atomicAdd in projection). Only instanceCount (word 1) must be GPU-written if geometry words are constant (matches splats). Do not write when conditioned-off: a compute node skipped by CPU condition leaves the previous count.
3. Render node: `resources:[... ,{buffer:h,usage:'indirect'}]` -> graph orders it after the writers and validates the buffer has INDIRECT usage. In `encode:({renderPass,getBuffer})`: with PR #3328: `model.setIndirectBuffer(getBuffer(h), offset)` (or constructor prop; getBuffer for imported buffers returns the same Buffer so it can be set once) then `model.draw(renderPass)`; without PR: `renderPass.setPipeline(model.pipeline); setVertexArray; setBindings(...); renderPass.drawIndirect(getBuffer(h), 0)` (what splats do). Model.draw also handles bind-group setup, which the manual path bypasses.
4. Gaps: (a) Model.draw inside graph nodes is unproven in splats (they bypass it); model.draw also does its own setBindings/uniform handling, check pipeline readiness (`model.pipeline.isErrored`). (b) Render nodes accept only CPU conditions; GPU-skip = instanceCount 0 in the record (note: with the PR, instanceCount:0 CPU no longer skips, record decides). (c) Render attachments: either graph `attachments` (graph-owned/imported textures, hazard-tracked) or getRenderPassProps({framebuffer}) with caller FB (not both); splats rely on the default canvas pass - for an offscreen deck-style target use getRenderPassProps framebuffer or imported texture views. (d) The graph opens/ends its own render pass; to draw into a deck-owned open pass (or composite with other layers) run compiled.encode BEFORE deck's pass (compute-only graph) and draw with Model.draw(renderPass) in the layer, as GPUCulledTraceLayer does; `predraw(commandEncoder)` pattern in splats-interaction (:223-235) is the compute-before-pass hook. (e) PR is open, unreviewed, WebGPU-only; Buffer needs INDIRECT usage at creation; DrawCommandBuffer enforces it. (f) alpha / private modules: gpgpu `gpu-core` is under docs/api-reference/experimental; vendored build predates PR.
